# Лабораторна робота №8
## Алгоритми пошуку та їх порівняння

Масив: Student[], 100 000 елементів.
Порівняння виконується виключно за полем Score.
X = 51, Y = 61, відсутнє значення = 101.

## Завдання 1. Лінійний пошук

Реалізовано узагальнений LinearSearch<T> із лічильником порівнянь.

| Запит | Індекс | Порівняння |
|---|---:|---:|
| X = 51 | 50280 | 50281 |
| Перший елемент | 0 | 1 |
| Бал 101 | -1 | 100000 |

Відсутній елемент потребує повного проходу масиву, тому цей запит найдорожчий.

## Завдання 2. Бінарний пошук

Реалізовано BinarySearch<T> із Func<T,T,int> та лічильником порівнянь.

| Запит | Індекс | Порівняння |
|---|---:|---:|
| X = 51 | 50780 | 7 |
| Перший елемент | 780 | 7 |
| Бал 101 | -1 | 17 |

### Чотири поломки

1. `lo < hi` замість `lo <= hi`:
   останній кандидат не перевіряється.
   Результат: `Broken 1: -1, 1`.

2. `lo = mid` замість `lo = mid + 1`:
   межа не рухається, цикл зависає.
   Результат: `Broken 2: -1, iterations: 20`.

3. `(lo + hi) / 2`:
   можливе переповнення int, коли сума індексів перевищує 2 147 483 647.
   Для 100 000 елементів помилка не проявляється.
   Результат: `Broken 3: 50780, 7`.

4. Несортований масив:
   бінарний пошук працює некоректно.
   Результат: `Broken 4: 82/100`.
   82 зі 100 наявних значень не знайдено.

## Завдання 3. LowerBound і UpperBound

Реалізовано один узагальнений метод пошуку межі з передаванням умови параметром.

| Операція | Результат | Порівняння |
|---|---:|---:|
| LowerBound X | 50280 | 17 |
| UpperBound X | 51288 | 17 |
| Кількість X | 1008 | 34 |
| Перший елемент >= X | 50280 | 17 |

Кількість студентів із балом 51:

`51288 - 50280 = 1008`.

Лінійний підрахунок потребує 100 000 перевірок.

Кількість порівнянь не залежить від кількості однакових елементів, оскільки область пошуку ділиться навпіл.

### Перевірка умови % 7

Результат:

`Condition %7: 100000, actual: 0, comparisons: 16`.

Правильний індекс — 0. Результат неправильний, оскільки умова кратності 7 не є монотонною відносно сортування за Score.

## Завдання 4. Інтерполяційний пошук

Реалізовано інтерполяційний крок із подальшим бінарним пошуком. Пропорція визначається за Score.

| Запит | Бінарний пошук | Інтерполяційний |
|---|---:|---:|
| X = 51 | 50780 (7) | 50999 (1) |
| Перший елемент | 780 (7) | 0 (1) |
| Бал 101 | -1 (17) | -1 (1) |

У дужках зазначено кількість порівнянь.

Інтерполяційний пошук ефективний за рівномірного розподілу значень. За нерівномірного розподілу та великої кількості повторів його ефективність може знижуватися.

## Завдання 6. Висновки

1. Експериментальна точка окупності — 100 000 запитів, що значно більше за теоретичні 34. Причина — витрати на копіювання та сортування масиву.

2. Бінарний пошук дозволяє знайти першого студента з балом не меншим за заданий і визначити кількість студентів у діапазоні балів. HashSet і Dictionary не підтримують пошук упорядкованих меж.

3. Для даних, які постійно змінюються, доцільно використовувати HashSet або Dictionary для точного пошуку. Якщо потрібні впорядковані діапазони, краще використовувати структуру з підтримкою порядку. Лінійний пошук підходить для невеликих масивів.
